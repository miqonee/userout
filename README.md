# Route Proxy & Client Portal

Шлюз к 9router, панель управления ключами и персональные кабинеты клиентов.

## Запуск в Docker

Нужны Docker и Docker Compose. Скопируйте `.env.example` в `.env` и заполните `ADMIN_PASSWORD`, `ROUTER_PASSWORD`, `ROUTER_URL` и `PUBLIC_URL`.

```powershell
Copy-Item .env.example .env
# Заполните .env перед запуском.
docker compose up -d --build
docker compose logs -f route-proxy
```

В Linux используйте `cp .env.example .env`. Node.js на хосте для запуска не требуется. Контейнер работает от пользователя `node`, проверяет `/health` и сохраняет данные в именованном томе `route-data`.

Кабинет клиента доступен по `/p/:token`. Адрес админки создаётся автоматически при первом запуске: `/manage-<24 случайных hex-символа>`. Он сохраняется в `/app/data/admin-path` вместе с базой в Docker-томе и остаётся прежним после перезапуска, пересоздания контейнера и обновления образа. Ручная настройка адреса не нужна. Главная и старый `/admin` возвращают 404.

При каждом запуске в логах есть запись с полным внешним адресом панели:

```text
"adminUrl":"https://your-domain.example/manage-...","msg":"Administration URL"
```

`PUBLIC_URL` должен содержать внешний адрес сервиса. Посмотреть адрес повторно: `docker compose logs route-proxy`. Для обновления: `docker compose up -d --build`; остановить без удаления данных: `docker compose down`. Том `route-data` содержит базу, блокировки входа и адрес панели; не удаляйте его при обычном обновлении.

Перед запуском задайте собственный `ADMIN_PASSWORD`: без него вход отключён, а Compose откажется запускаться с пустым паролем.

Защита входа: 5 неверных паролей с одного IP → блокировка на 15 минут; 30 неверных паролей суммарно → общая блокировка на 15 минут. Ответ — HTTP 429 с `Retry-After`. Счётчики хранятся в SQLite и сохраняются после перезапуска. Сессии случайные, действуют 8 часов и отзываются при выходе или смене пароля; в базе хранится хеш токена. Cookie доступна только на пути панели, с `HttpOnly`, `SameSite=Strict` и `Secure` для HTTPS. Старые сессии после обновления нужно заменить новым входом.

По умолчанию `X-Forwarded-For` не используется. За reverse proxy укажите в `TRUST_PROXY` только его доверенные IP/CIDR, чтобы лимит учитывал реальный адрес посетителя. Не перечисляйте клиентские сети или весь интернет. Это соответствует модели доверенных прокси [Fastify](https://fastify.dev/docs/latest/Reference/Server/#trustproxy); политика блокировок учитывает рекомендации [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#login-throttling).

## Демо интерфейса

```powershell
npm run preview
```

- Случайный адрес панели выводится в консоли при запуске; пароль `route-preview`.
- Кабинет: http://127.0.0.1:3100/p/demo-1.
- Исчерпанный пакет: `/p/demo-4`, безлимитный: `/p/demo-6`.
- Другой порт: `$env:PREVIEW_PORT=3200; npm run preview`.

Для разработки нужен Node.js 22.13 или новее; сначала выполните `npm ci`. Демо запускает настоящий сервер приложения с локальной имитацией 9router. Оно использует синтетические ключи и отдельную временную SQLite-базу; рабочие данные и внешний шлюз не затрагиваются. При каждом запуске демо создаются новый набор примеров и новый адрес админки. Остановка — `Ctrl+C`.

## Что изменено в дизайне

Прежний интерфейс состоял из почти одинаковых полупрозрачных карточек, мелких подписей и ярких градиентов. Форма создания ключа отодвигала ежедневную работу со списком клиентов вниз страницы.

Панель администратора строится вокруг задач: обзор квот → поиск клиента → действие с ключом. Графитовая навигация, светлые поверхности и сдержанный зелёный акцент задают общую систему. Форма выпуска открывается в отдельном окне; таблица поддерживает поиск и фильтры.

Клиент получает единственную страницу по криптографически случайному адресу `/p/:token`, без бокового меню и входа в панель. На ней находятся квота, ключ и инструкции по подключению. Страница и API статуса отдают `X-Robots-Tag: noindex, nofollow, noarchive`, `Cache-Control: private, no-store, max-age=0` и `Referrer-Policy: no-referrer`; в HTML также указан `noindex`. После исчерпания квоты страница возвращает `410 Gone` без ключа и примеров настройки. Открытая вкладка проверяет квоту каждые 15 секунд и при возвращении на страницу.

Для OpenCode доступны готовая инструкция с URI, ключом и моделями и JSON-конфиг. Для Codex CLI — отдельный профиль в `config.toml` и команды PowerShell/bash. Модели автоматически берутся из настроек выданного ключа; для ключа без ограничений загружается доступный ему каталог шлюза. Клиенту не нужно вводить или выбирать модель. Конфиг OpenCode включает все выданные модели; первая используется по умолчанию в примерах. Codex требует поддержки Responses API и вызова инструментов на стороне шлюза и модели; наличие ключа само по себе её не подтверждает. Форматы настроек сверены с [официальной документацией OpenCode](https://docs.opencode.ai/docs/providers/#custom-provider) и [Codex](https://learn.chatgpt.com/docs/config-file/config-advanced).

Оформление и иконки локальные: Tailwind CDN, внешние шрифты и сборщик для страниц не требуются. Общие стили, иконки и поведение находятся в `src/views/ui.js`; формат чисел общий для первого отображения и последующего обновления квоты.

## Проверка

```powershell
npm test
```

Проверки охватывают экранирование пользовательских данных, синтаксис встроенных скриптов, отсутствие секретов в исчерпанном кабинете, безлимитные ключи и границы округления квоты. Адаптивная вёрстка, создание/удаление ключа, поиск, фильтры, копирование и инструкции проверяются в демо.
