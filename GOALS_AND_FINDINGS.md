# Цели приложения и технические находки по 9router

Документ фиксирует назначение проекта **Route Proxy & Client Portal**, его архитектуру, а также результаты реверс-инжиниринга и живого тестирования API форка **9router**.

---

## 1. Цели приложения (Project Goals)

### Основная проблема
Есть работающий инстанс **9router**, подключенный к upstream-провайдерам (Antigravity, Cline, GLM, LiteLLM и др.).
Прямая выдача доступа клиентам несет риски:
1. **Утечка эндпоинта и конфигурации:** клиенты видят реальный домен, дашборд и настройки 9router.
2. **Отсутствие клиентского портала:** клиенты не видят остаток своей квоты в реальном времени и не знают, как правильно настроить свои клиенты (Cursor, Claude Code, Python SDK и др.).
3. **Рутина управления:** нет удобного инструмента для пакетного выпуска ключей с фиксированными лимитами (10M / 50M / 100M токенов) и генерации продающих сообщений для Telegram.

### Задачи сервиса-прослойки
1. **Маскировка эндпоинта (Reverse Proxy `/v1/*`):**
   - Клиенты отправляют запросы только на домен прокси (например, `https://ai.yourdomain.ru/v1`).
   - Прокси прозрачно транслирует запросы в 9router через внутреннюю Docker-сеть Coolify (`http://9router:20128`), скрывая 9router от публичного интернета.
   - Нулевая задержка (TTFT): стриминг SSE передается чанками без буферизации.

2. **Персональная страница покупателя (`/p/:secret_id`):**
   - Доступ по уникальной криптографической ссылке без логина и пароля.
   - Виджет квоты: живой прогресс-бар (`Израсходовано X млн / Y млн токенов`).
   - Креды: Base URL и персональный API-ключ с кнопками копирования в 1 клик.
   - Список купленных моделей (клиент видит только те модели, за которые заплатил).
   - Интерактивные вкладки с инструкциями:
     - **Cursor / VS Code:** параметры Base URL и точные названия моделей.
     - **Claude Code / OpenCode CLI:** готовая команда экспорта переменных окружения.
     - **Python / Node.js:** готовые сниппеты с OpenAI SDK.
     - **cURL:** готовая команда проверки в терминале.

3. **Логика деактивации / «самоуничтожения»:**
   - Как только лимит токенов исчерпан (`usedTokens >= tokenLimit`):
     - API 9router возвращает HTTP `429 Quota Exceeded`.
     - Персональная страница деактивируется: креды удаляются из интерфейса и заменяются на сообщение об исчерпании квоты с контактами для продления.

4. **Панель администратора (`/admin`):**
   - Вход по мастер-паролю прокси.
   - Пакетная генерация ключей с выбором лимита (10M / 50M / 100M / Custom) и выбором моделей (подтягиваются прямо из 9router).
   - Кнопка «Скопировать для Telegram» — формирует готовое сообщение покупателю с персональной ссылкой.
   - Таблица мониторинга всех выданных ключей с актуальным расходом токенов.

5. **Развертывание в Coolify:**
   - Готовый `Dockerfile` и `docker-compose.yml` для деплоя двух контейнеров в единую изолированную сеть `bridge`.

## 2. Технические находки по форку 9router

### 2.1 Подсчет и списание токенов (Исследование исходного кода)
Анализ репозитория `9router` показал, что форк уже имеет полную встроенную систему биллинга токенов:

1. **Списание токенов (`src/lib/db/repos/usageRepo.js:293-300`):**
   После завершения любого запроса (и обычного JSON, и стриминга SSE) вызывается:
   ```javascript
   const totalTokens = (promptTokens || 0) + (completionTokens || 0);
   if (totalTokens > 0) {
     db.run(`UPDATE apiKeys SET usedTokens = COALESCE(usedTokens, 0) + ? WHERE key = ?`, [totalTokens, cleanKey]);
   }
   ```
2. **Проверка лимита и возврат HTTP 429 (`src/sse/services/auth.js:500-506`):**
   ```javascript
   if (keyRecord.tokenLimit > 0 && keyRecord.usedTokens >= keyRecord.tokenLimit) {
     return {
       valid: false,
       error: `Token limit exceeded for this API key (${keyRecord.usedTokens.toLocaleString()} / ${keyRecord.tokenLimit.toLocaleString()} tokens used)`,
       status: 429,
     };
   }
   ```
3. **Ограничение по моделям (`src/sse/services/auth.js:507-513` и `keyAccess.js`):**
   Если запрошенная модель не входит в `allowedModels`, 9router возвращает:
   ```json
   HTTP/1.1 403 Forbidden
   {"error": {"message": "Model '...' is not allowed for this API key", "type": "permission_error", "code": "insufficient_quota"}}
   ```

### 2.2 Модель безопасности и авторизация эндпоинтов 9router
В файле `src/dashboardGuard.js` реализовано строгое разграничение:
1. **Инференс-эндпоинты (`/v1/*`):**
   - Доступны публично при наличии валидного Bearer-токена (`sk-...`).
2. **Управляющие эндпоинты (`/api/keys`, `/api/usage`, `/api/settings`):**
   - Защищены `dashboardGuard`.
   - Запросы с ключами инференса (`sk-...`) отклоняются с кодом `401 Unauthorized`.
   - Для доступа требуется авторизационная кука `auth_token` (JWT HS256, 24h), выдаваемая при логине в админку.

### 2.3 Результаты живого тестирования API на `https://route.fn.x3dev.ru`

В ходе реальных HTTP-запросов подтверждено:

1. **Авторизация администратора (`POST /api/auth/login`):**
   ```bash
   POST https://route.fn.x3dev.ru/api/auth/login
   Body: {"password": "<ROUTER_PASSWORD>"}
   ```
   **Результат:** `200 OK`, возвращает заголовок `Set-Cookie: auth_token=...; Max-Age=86400; HttpOnly; SameSite=lax`.

2. **Создание ключа (`POST /api/keys`):**
   ```bash
   POST https://route.fn.x3dev.ru/api/keys
   Cookie: auth_token=...
   Body: {
     "name": "Test Key",
     "tokenLimit": 10000000,
     "allowedModels": ["ag/gemini-3.8-flash-low", "cl/z-ai/glm-5.2:free"]
   }
   ```
   **Результат:** `201 Created`, возвращает объект:
   ```json
   {
     "id": "fd3c280e-87c4-48b6-8539-19589f0fd305",
     "key": "sk-1c132b4019cec308-wrbmlu-05c55fe1",
     "tokenLimit": 10000000,
     "usedTokens": 0,
     "allowedModels": ["ag/gemini-3.8-flash-low", "cl/z-ai/glm-5.2:free"]
   }
   ```

3. **Инференс и списание токенов (`POST /v1/chat/completions`):**
   - Запрос к разрешенной модели `ag/gemini-3.8-flash-low` вернул `200 OK` (стриминг SSE).
   - Финальный чанк вернул `usage: { prompt_tokens: 2005, completion_tokens: 1, total_tokens: 2006 }`.
   - Последующий запрос `GET /api/keys/:id` показал автоматическое обновление: `"usedTokens": 6`.

4. **Блокировка запрещенных моделей:**
   - Запрос с этим же ключом к неразрешенной модели `ag/gemini-3.8-flash-high` мгновенно вернул `403 Forbidden` с сообщением: `Model 'ag/gemini-3.8-flash-high' is not allowed for this API key`.

5. **Удаление ключа (`DELETE /api/keys/:id`):**
   - Успешно удаляет ключ с кодом `200 OK` и сообщением `{"message": "Key deleted successfully"}`.

## 3. Архитектурное решение

Сервис-прослойка строится на **Node.js 22 + Fastify**:
- Хранит сессию взаимодействия с 9router (автоматически обновляет `auth_token` при старте и по истечении срока).
- Имеет локальную базу SQLite для хранения связки: `portal_token (секрет ссылки) <-> 9router_key_id <-> 9router_key`.
- Предоставляет:
  - `/v1/*` — прозрачный обратный прокси.
  - `/p/:token` — персональный фронтенд покупателя.
  - `/admin` — панель управления и пакетной генерации.
